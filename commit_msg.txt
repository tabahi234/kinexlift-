Three bugs the browser caught

A settings field that read two different ways. Profiles created in P1 have no readinessAdjustments value. The planner treated undefined as on; the screen treated it as off. So weights would have been quietly adjusted under a banner saying adjustments were off. Now one adjustmentsEnabled() helper decides.

"Eased from 6 kg" next to 6 kg. 5% off a light dumbbell rounds back to where it started. applyReadiness now returns the prescription untouched when nothing actually moved.

The note named the wrong thing. Where only a set was dropped, it still talked about weight. It now lists only what genuinely changed.

What I verified, and what I didn't
I walked a red-scoring day end to end in the browser: check-in -> red banner -> adjusted weights and set counts -> override -> restore -> settings toggle -> dark mode.
